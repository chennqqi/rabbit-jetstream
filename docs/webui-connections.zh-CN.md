## 候选页面

列表 CID 现链接至 `/admin/nodes/{id}/connections/{cid}?offset=…&limit=…`。这些查询字段仅保留返回列表上下文，不转发给详情 API。候选详情展示范围身份、来源时间及精确数值计数，独立刷新并区分节点缺失与连接缺失。新页面已取得 Chromium/Firefox 真实导航/刷新/错误及桌面/移动端证据，完整可访问性与发布就绪仍是独立门槛。不增加客户端元数据、搜索或订阅详情。

两个来源时间字段均要求有效 RFC3339 日历日期、明确时区及最多九位小数。Go 零时间视为未报告/无效，不是真实观测。校验保留原文本，不规范化无效日期，不截断来源精度。

节点详情可进入 `/admin/nodes/{id}/connections?offset=0&limit=50`。页面在 URL 中保留节点/查询身份，提供页大小及前后翻页，复用刷新偏好。显示精确 CID/计数、报告总数与返回行数、未舍入的服务端和管理时间戳，以及中英文说明。不提供尚未支持的搜索、客户端身份或订阅详情控件。逐查询读取器取消过时请求；不可用时保留明确标记的历史页，缺失/歧义/拒绝/禁用/无效响应清空。畸形身份、计数和分页在展示前校验失败。连接累计计数不是 Consumer 积压或速率。移动端表格横向滚动以保留数字可读性；完整可访问性验收仍未完成。

## 节点连接 API

`GET /api/v1/nodes/{node}/connections?offset=0&limit=50` 返回下述数值连接投影。遵循已有资源读取策略：默认要求 operator/auditor 认证，或采用显式本机演示资源读取例外。未授权 GET/HEAD 在监控 I/O 前拒绝。响应使用 `Cache-Control: no-store`。接受无符号十进制 offset（0–1,000,000）、limit（1–200）和可选精确 `cid`（1–18446744073709551615），省略 offset/limit 时默认 0/50。CID 搜索要求 offset 为零，由服务端在精确节点范围执行，过滤后总数为零或一。未知、重复、空、畸形或越界参数返回 400。客户端名称搜索、客户端元数据和订阅详情尚未支持，不以当前页过滤模拟。

响应字段：`node_id`、`observed_at`（NATS 来源时间）、`read_at`（管理读取完成）、原始 `offset`、`limit`、`total` 及 `items`。普通分页的 total 是节点报告总数；精确 CID 搜索的 total 是过滤后结果数。每项包含精确 uint64 `cid` 和可选非负计数，缺省计数表示未知。错误映射：400 `invalid_query`；完整身份覆盖后 404 `not_found`；409 `node_identity_ambiguous`；503 `connection_lookup_limit` 或 `connections_unavailable`。认证可返回 401/403 或 404 `read_api_disabled`。缺少监控能力及未知内部错误返回脱敏 503，不返回空成功。见 [OpenAPI](../api/openapi.yaml)。

`POST /api/v1/nodes/{node}/connections/search` 是遵循资源读取授权的只读端点，JSON 请求体必须包含精确 `kind`、`value`、`offset` 和 `limit`，不接受 URL 查询。kind 支持 `name`、`user`、`account` 和 `mqtt_client`。用户／账户／MQTT 过滤在固定服务端分页前执行；由于上游返回节点总数，管理服务执行两次稳定扫描并计算过滤总数。固定服务端没有名称过滤器，因此只有完整节点打开连接不超过 1,000 时才允许名称搜索；两次完整私有 CID／名称读取必须一致，之后管理服务才过滤、分页并只返回数值行。原生过滤匹配超过 1,000 条，或名称搜索节点总连接超过 1,000 个，均返回 422。搜索值不会被序列化、不会由请求日志记录、不会进入浏览器 URL，也不会被 UI 持久化。

## 已实现边界

`monitoring.Client.ConnectionPage` 从按索引选择的预配置监控端点读取一页打开的连接。调用方提供此前节点观测的预期 server ID，响应必须匹配。稳定端点也可能服务重启后或其他服务器，因此端点本身不足以证明身份。连接身份是 server ID 与精确 uint64 CID 的组合，不能仅使用 CID。

固定版本的 `upstream/nats-server/server/monitor.go` 提供线格式契约：CID 升序、`total` 与返回的 `num_connections` 独立、越过最后一行仍保留原请求偏移、实时而非快照分页。本实现允许资源变化导致页缩短，保留总数和请求偏移，拒绝重复/乱序/零 CID 及不可能的元数据。未报告计数保持缺省，不补零。

限制：偏移 0–1,000,000；每页 1–200；响应最多 2 MiB。遵循已有 HTTP 超时及调用方 context。拒绝重定向，不跟随；错误不包含端点凭据或原始响应文本。固定请求 `auth=false`、`subs=false`、`state=open`、`sort=cid`。投影仅包含 CID 和数值计数，排除名称、地址、认证/JWT/账户元数据、证书、订阅 Subject 及上游原始 JSON；不转发未知上游字段。这不是最终客户端搜索投影。

## 精确节点解析

`NodeConnections` 现可在内部解析精确节点 ID。仅从配置端点读取 `/varz`，复用 2 MiB/禁止重定向传输边界。最多接受 32 个配置端点，身份读取并发为 4，解析和连接读取共享 5 秒期限（调用方更早的期限优先）。非法输入在 I/O 前拒绝；超过限制明确报错，不静默截断。

所有身份读取必须成功且恰好一个匹配。多个匹配表示歧义；部分覆盖即使观察到一个匹配也返回不可用，因为唯一性未知。只有完整有效覆盖后的无匹配才表示缺失；未配置端点表示不可用。不静默合并重复端点别名，不缓存身份，不回退到其他节点/名称。后续连接响应仍必须匹配选定 server ID，两次读取之间发生重启则返回不可用。这些读取不证明跨端点原子成员快照。内部错误具有可区分类型，不包含端点 URL 或原始响应。公开 API 和 UI 现已在既有读取授权下支持精确节点范围 CID 搜索；敏感的客户端名称搜索仍有意保持不可用。
