# v0.1.0-rc.3 发布说明

[English](v0.1.0-rc.3.md) | [简体中文](v0.1.0-rc.3.zh-CN.md)

本候选版本将评审加固线（A1–A15）冻结为确切的 rc.3 候选，并完成了 rc.2 遗留的两个重量级资格门槛：42 小时裸金属 soak 与完整的 helm/Kind 三 worker 集群资格。同时调和了在相同范围内并行推进的 origin 线合并。

## 亮点

- **稳定性**：修复了未配置 Prometheus 后端时告警监控路径空指针击溃整个管理进程的控制面崩溃；管理服务现在对任何依赖配置错误都以干净的降级状态存活。
- **运维深度**：按队列死信归因（`rjs_dlq_queue_{moved,failed}_total`，DeadLetterFailures 告警改写为 `sum by (queue)`）、删除预检的 DLQ 依赖方检查，以及运维配套清单（Alertmanager 基线、消息级排障旁路、备份 cron、值班 runbook）。
- **管理控制台**：状态徽章体系（token 派生、对比度已验证）、导航分组与列表页头创建入口、顶栏平铺身份与会话过期一键恢复、免责声明折叠为"关于这些数字"、刷新状态指示器、hash 截断复制、字节人性化、移动端与表格溢出修复。
- **行尾策略**：`.gitattributes` 在所有平台固定文本文件为 LF；本仓库禁用 `core.autocrlf`。
- **合并卫生**：origin 并行线已调和到冻结候选之上——代码以资格树为准；origin 的完成度评估文档与 compose 参数化保留。

## 资格证据（绑定此确切树）

- **42 小时裸金属 soak**（要求 24 小时）：5053 个证据周期，管理健康与 Queues API 每周期 HTTP 200，零组件崩溃，管理日志零错误，453,505 条消息以约 3 条/秒持续写入。见 [soak 证据](v0.1.0-rc.3-soak-evidence.zh-CN.md)。
- **helm/Kind 三 worker 集群资格**：production profile 安装（R3、mTLS、PDB、NetworkPolicy、egress）、NATS 分布于三个 worker、三个 PVC Bound、auth Secret 二次升级稳定、management 与 NATS NetworkPolicy 正负向验证、两处 PDB 二次驱逐被拒、readyz + Admin UI + `cluster` profile 上报验证、卸载干净且 PVC 保留。见 [集群资格证据](v0.1.0-rc.3-cluster-evidence.zh-CN.md)。
- **本地门禁**：Go 套件全绿、S-4 视觉矩阵（96 张截图）通过、Playwright Chromium+Firefox 8/8 且 axe serious/critical 零违规、dist 内嵌验证干净。三个 Windows 专属 jsdom 测试在 win32 跳过（vite SSR 盘符路径缺陷）；同等断言由 Playwright 套件覆盖。

## 资格 Profile

- Linux/AMD64，三 JetStream 节点，三流副本（与 rc.2 一致）。
- At-least-once 投递；应用必须幂等消费。

## 已知限制

- chart 的 helm test hook 固定的 busybox digest 在无 docker.io 出口的主机无法解析；等价的"经 Service 的 readyz"断言由 NetworkPolicy 正向检查覆盖（记录于集群资格文档）。
- 三个 Windows jsdom 测试因上述 vite SSR 盘符缺陷在 win32 跳过；Linux CI 真实执行。
- 消息级运维（浏览/重放）按架构保持在管理面之外；使用配套清单的旁路流程。

## GA 前剩余事项

Canary 分阶段（1–100% 流量）、节点故障演练、回滚演练与 sole-owner 签字需要真实部署环境，跟踪于 `docs/remaining-release-work.md` 与 release-approval 模板。
