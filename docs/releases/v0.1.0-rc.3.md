# v0.1.0-rc.3 Release Notes

[English](v0.1.0-rc.3.md) | [简体中文](v0.1.0-rc.3.zh-CN.md)

This release candidate freezes the review-hardening line (A1–A15) as the exact rc.3 candidate and completes the two heavyweight qualification gates that rc.2 left open: a 42-hour bare-metal soak and the full helm/Kind three-worker cluster qualification. It also resolves an origin-line merge that ran the same scope in parallel.

## Highlights

- **Stability**: fixes a control-plane crash where an unconfigured Prometheus backend could panic the whole management process (alert watcher nil dereference); the management service now survives any dependency misconfiguration with a clean degraded state.
- **Operations depth**: per-Queue dead-letter attribution (`rjs_dlq_queue_{moved,failed}_total` with the DeadLetterFailures alert rewritten to `sum by (queue)`), DLQ-dependency checks in the delete preflight, and an operations companion checklist (Alertmanager baseline, message-level troubleshooting sidestep, backup cron, on-call runbooks).
- **Admin console**: status badge system (token-derived, contrast-verified), navigation grouping with create-in-list-header, flat top-bar identity with a one-click expired-session recovery, disclaimers folded into "about these numbers" notes, refresh-state indicators, hash truncation with copy, humanized byte counts, and mobile/table overflow fixes.
- **Line-ending policy**: `.gitattributes` pins LF for all text files on every platform; `core.autocrlf` disabled for this repository.
- **Merge hygiene**: the parallel origin line was reconciled onto the frozen candidate — code resolved to the qualified tree; origin's completion-assessment document and compose parameterization were kept.

## Qualification Evidence (bound to this exact tree)

- **42-hour bare-metal soak** (requirement: 24 h): 5053 evidence cycles, management health and Queues API HTTP 200 in every cycle, zero component crashes, zero errors in the management log, 453,505 messages sustained at ~3 msg/s. See [soak evidence](v0.1.0-rc.3-soak-evidence.md).
- **helm/Kind three-worker cluster qualification**: production-profile install (R3, mTLS, PDB, NetworkPolicy, egress), NATS spread across three workers, three PVCs Bound, auth Secret stable across re-upgrade, management and NATS NetworkPolicy positive+negative verified, both PDB second evictions denied, readyz + Admin UI + `cluster` profile report verified, clean uninstall with PVCs retained. See [cluster evidence](v0.1.0-rc.3-cluster-evidence.md).
- **Local gates**: Go suite green, S-4 visual matrix (96 screenshots) pass, Playwright Chromium+Firefox 8/8 with zero axe serious/critical violations, dist embed verification clean. Three Windows-only jsdom tests skip on win32 (vite SSR drive-letter path defect); identical assertions are covered by the Playwright suite.

## Qualified Profile

- Linux/AMD64, three JetStream nodes, three stream replicas (unchanged from rc.2).
- At-least-once delivery; applications must consume idempotently.

## Known Limitations

- The chart's helm test hook pins a busybox digest that cannot resolve on hosts without docker.io egress; the equivalent readyz-through-Service assertion is covered by the NetworkPolicy positive check (recorded in the cluster evidence).
- Three Windows jsdom tests skip on win32 per the vite SSR drive-letter defect noted above; Linux CI runs them for real.
- Message-level operations (browse/replay) remain outside the management plane by architecture; use the companion checklist's sidestep procedures.

## Remaining Before GA

Canary stages (1–100 % traffic), node-failure drill, rollback drill, and sole-owner sign-off require a live deployment environment and are tracked in `docs/remaining-release-work.md` and the release-approval template.
