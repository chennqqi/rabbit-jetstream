# v0.1.0-rc.1 Release Notes

[English](v0.1.0-rc.1.md) | [简体中文](v0.1.0-rc.1.zh-CN.md)

This is the first release candidate of the native JetStream queue distribution.

## Highlights

- Pinned NATS Server/JetStream `v2.14.1` server core without management-feature source modifications.
- Management API, embedded Admin UI, audit, authentication, diagnostics, migration, backup/restore, and `rjsctl`.
- Native Go SDK with bounded strict-priority scheduling, PubAck, Ack/Nak/Term, backpressure, redelivery, and reconnect recovery.
- Standalone and three-node Compose deployments plus a production-oriented Helm chart.

## Qualified Profile

- Linux/AMD64, three JetStream nodes, three stream replicas.
- Up to eight priority levels (`MaxPriority <= 7`).
- At-least-once delivery; applications must consume idempotently.
- 24-hour 5,000 msg/s integrity soak with 432 million messages and zero missing, duplicate, or corrupt messages.

## Known Limits

- No RabbitMQ/AMQP wire compatibility; existing AMQP clients cannot connect unchanged.
- ARM64 artifacts are cross-built but not production-qualified.
- More than eight priorities are experimental.
- Throughput results are qualification baselines, not universal SLAs.

Verify the bundle with `sha256sum -c SHA256SUMS`. Deploy immutable image digests and follow the staged canary and rollback runbook before GA promotion.
