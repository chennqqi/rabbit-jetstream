## 环境适配（为可追溯性记录）

1. **镜像由冻结二进制组装**：主机不可达 gcr.io/docker.io，且按策略不传输源码树——三个候选镜像在主机上由冻结 linux/amd64 二进制叠加固定 distroless 基础镜像组装（`COPY --chmod=755`），与 `packaging/Dockerfile.*` 运行时阶段语义一致。
2. **基础镜像经 DaoCloud 镜像源**：`gcr.m.daocloud.io` / `docker.m.daocloud.io` 提供 distroless、kindest/node、alpine/helm、busybox。
3. **kind 使用 rootful podman**：rootless 变体产生 containerd 镜像元数据视图分裂（ctr 与 CRI 对同名记录不一致），破坏 digest 引用；rootful podman 与脚本编写时的 docker provider 行为一致。
4. **helm test hook 环境受阻**：chart test hook 固定 `busybox:1.37.0@sha256:9db7...`，在无 docker.io 出口的主机上无法解析。等价断言（经 management Service 的 HTTP readyz）由 NetworkPolicy 正向检查使用候选 management 二进制自带的 healthcheck 客户端覆盖。记录为环境受阻，非候选缺陷。
5. **探测工具**：NetworkPolicy 探测使用候选镜像自带二进制（`rjsctl status` 验 HTTP，`nats rtt` 验 TCP+TLS），替代 busybox wget/nc。
