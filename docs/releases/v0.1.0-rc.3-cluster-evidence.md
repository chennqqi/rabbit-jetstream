## Environment adaptations (recorded for traceability)

1. **Images from frozen binaries**: the host cannot reach gcr.io/docker.io, and the source tree is not transferred per policy — the three candidate images were assembled on the host from the frozen linux/amd64 binaries over the pinned distroless base (`COPY --chmod=755`), semantically identical to `packaging/Dockerfile.*` runtime stages.
2. **Base images via DaoCloud mirror**: `gcr.m.daocloud.io` / `docker.m.daocloud.io` for distroless, kindest/node, alpine/helm, busybox.
3. **Rootful podman for kind**: the rootless variant produced a split containerd image-metadata view (ctr vs CRI disagreed on identical names), breaking digest references; rootful podman behaves like the docker provider the script was written for.
4. **helm test hook environment-blocked**: the chart test hook pins `busybox:1.37.0@sha256:9db7...`, which cannot resolve on a host without docker.io egress. The equivalent assertion (HTTP readyz through the management Service) is covered by the NetworkPolicy positive check using the shipped management binary's own healthcheck client. Recorded as environment-blocked, not a candidate failure.
5. **Probe tools**: NetworkPolicy probes use the candidate images' own binaries (`rjsctl status` for HTTP, `nats rtt` for TCP+TLS) instead of busybox wget/nc.
