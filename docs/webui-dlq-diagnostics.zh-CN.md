# Queue DLQ 诊断

[English](webui-dlq-diagnostics.md) | [简体中文](webui-dlq-diagnostics.zh-CN.md)

Queue 配置页现包含只读 DLQ 诊断区域（WEB-022）。使用已读取声明的 Plan 作为期望配置，不作为实时转移结论。无 DLQ 时显示未配置，不发额外请求。不支持的机制、非法名称或自引用会阻止关联读取。

对于 `advisory-republish` 目标，页面独立读取精确目标声明及当前管理进程的控制器状态。仅当目标声明的 Queue 身份、Plan 版本及目标 Stream 映射一致时，才允许读取该 Stream。不继续跟随目标自身的 DLQ 依赖。因此每次刷新最多发送三个已有 GET，不全账户枚举，不发布、确认、重试、重放或修改消息/资源。取消可阻止离开页面后的迟到结果及后续链式读取。

页面区分已观测、缺失、拒绝访问、不兼容、不可用和未观测。目标声明缺失不代表 Stream 缺失：没有读取过的 Stream 保持未观测。失败清除旧证据，成功来源保留各自读取时间。源声明、目标 ETag、Stream 存在性及控制器状态不是原子快照。刷新 DLQ 证据不替换源声明，须使用整页刷新重读源声明。存在不证明目标所有权、就绪或转移成功，精确目标链接提供独立声明/Stream 检查入口。

展示控制器标志、实例、上次运行、上次成功运行及是否存在错误，不生成虚构健康结论。Go 零值时间表示未报告。原始错误文本不复制到模型。DLQ 已处理/已转移/失败计数是此控制器进程对**所有 Queue**的累计报告，可能重置，不是完整事件台账。缺失计数保持未报告，零值和大整数精确保留。无错误或禁用/非 Leader 状态不能解释为当前 Queue 成功/失败。逐 Queue 转移历史和完整转移健康契约仍需后端增加观测能力，尚未实现。

测试覆盖一层读取、目标缺失/拒绝/不可用、映射不一致、非法/自引用 Plan、控制器失败、精确计数、时间戳、隐私和取消链式请求。隔离真实服务测试创建两个专用空 Queue（`live_dlq_source`、`live_dlq_target`），验证真实目标声明/Stream 读取，注入一次目标 404 检查 Stream 未观测提示，再恢复并确认诊断不产生 PUT。不发布消息，不证明实际 DLQ 转移。这些资源仅位于测试自建 Broker，禁止针对已有服务运行此样例。

## 后端计数语义

控制器时间要求真实 RFC3339 日历日期、明确时区及最多九位小数。合法来源字符串保留原精度和偏移。仅精确 `0001-01-01T00:00:00Z`（也允许全零小数）视为未报告；非法时间使控制器证据不兼容，导出不包含其值。任一 DLQ 来源的畸形 JSON 也视为不兼容，HTTP 401/403 则仍为访问被拒绝。某个来源校验失败不会清除其他独立有效来源。

后端计数语义：即使批次随后报告读取或确认错误，也保留部分处理结果；本次运行仍报告失败，不推进上次成功时间。这些是处理尝试计数，不是去重消息数：重新投递的事件可重复计数，`moved` 也可能包含源消息已不存在的情况。某批次即使没有批次级错误，也可能报告失败的转移尝试。不得把 `moved` 解释为新增目标消息数量的证明，也不得把 `lastSuccess` 解释为每次转移均成功。

## 已忽略事件尝试

`GET /api/v1/controller` 现包含 `dlqIgnored`，与 `dlqProcessed`、`dlqMoved`、`dlqFailed` 及运行状态在同一锁内累加，包括部分失败批次。它表示事件 JSON 无法解码，或事件 Stream/Consumer 未匹配该批次声明来源的处理尝试，不证明消息丢失、确认已完成或业务规则拒绝。这是增量字段：旧服务端可能省略，界面显示未报告，本地导出保留缺失。当前后端明确报告零值；前端/导出仍无损保留精确大整数。

控制器响应的计数字段示例（不是逐 Queue 统计）：

```json
{"instanceId":"management-1","dlqProcessed":10,"dlqMoved":4,"dlqFailed":2,"dlqIgnored":4}
```

Prometheus 同时新增 `rjs_dlq_processed_total` 和 `rjs_dlq_ignored_total`，仅按控制器实例标记。已有 moved/failed 指标名称不变；moved 帮助文本现明确包含源消息已不存在的情况，不代表去重转移数。指标沿用既有浮点输出路径，不具备 JSON/导出的精确整数保证。未新增事件存储、原因台账、Queue 标签，也未改变消息处理、重试或确认行为。

## 本地证据下载

就绪状态按来源独立：目标不存在时，Stream 可保持未观测而控制器仍在读取。刷新按钮在所有来源均不处于加载态后恢复；传输超时将对应来源转为不可用，允许再次显式读取。测试覆盖控制器停滞、超时恢复及迟到结果隔离。浏览器报告现包含允许列表内的 DLQ 请求耗时，导出就绪失败时另存来源状态和区域截图。此前一次 Chromium 五秒就绪失败仍未定位，尽管重跑通过；见[执行记录](webui-development.zh-CN.md)。

“下载 DLQ 证据 JSON”保存 `rjs.dlq-diagnostic-evidence.v1`：原始源 Queue/Plan 版本/声明 ETag/读取时间及目标映射，再附各已读取来源的状态与时间。仅已观测来源包含白名单值。不可用来源不导出残留旧值或原始错误。控制器计数保持整数精度及进程级范围。文件不包含凭据、完整声明、任意原始后端响应或逐 Queue 消息历史。

下载仅创建本机浏览器 Blob，不发送 API 请求、不重新读取或修改。观测变化时替换准备好的下载，旧 Blob URL 会释放。准备失败会明确提示，不清除页面证据。下载包含运行/配置元数据，清除会话后文件仍保留在磁盘。文件明确说明不保证原子性、完整性、所有权/就绪或转移结果归因。
