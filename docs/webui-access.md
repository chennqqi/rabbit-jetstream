# WebUI resource-read access policy

[English](webui-access.md) | [简体中文](webui-access.zh-CN.md)

Status: owner-approved D-05, implemented in source, not deployed. D-04 separately approves React/Vite compiled into Go-embedded static assets, without a runtime frontend server or CDN.

The management application requires operator or auditor bearer authentication for resource GET/HEAD requests under `/api/v1/`, including info, cluster, nodes, controller, Queues, Streams and Consumers. Missing/invalid credentials return 401; insufficient role returns 403; absent authentication configuration returns 404 `read_api_disabled`. Configure the existing `RJS_ADMIN_TOKEN`/`RJS_ADMIN_TOKENS`, `RJS_AUDIT_TOKENS` or OIDC settings before upgrading clients. Never put tokens in URLs, committed files or browser persistent storage.

Compatibility: anonymous API clients and the legacy dashboard's anonymous reads will no longer work by default. Update callers to send `Authorization: Bearer …`. The production React login/API integration is still outstanding; this source change alone does not make the dashboard ready. Existing frozen binaries and remote qualification are unchanged.

Only `RJS_LOCAL_DEMO=true` together with a literal loopback bind such as `RJS_HTTP_ADDR=127.0.0.1:8223` or `[::1]:8223` enables anonymous resource reads. Wildcard, private/public IP and DNS-name binds (including `localhost`) fail startup in demo mode, before backend initialization. The default is false; invalid Boolean values do not enable demo. Forwarded headers do not grant an exception. A reverse proxy or tunnel can still expose a loopback listener: do not publish this demo listener through either. Container port publication is not a supported way to enable this exception.

Demo never bypasses session, audit, preview or write authorization. `/healthz`, `/readyz`, `/metrics`, `/admin/`, `/api/v1/openapi.yaml` and `/api/v1/native-sdk-contract.json` remain public; restrict monitoring/static exposure with network controls. Public static assets are not permission to read protected resources. Session reports `resource_read_policy=authenticated` by default and `anonymous` for demo.

The public readiness failure response is deliberately limited to `{"status":"not_ready"}`. Service logs record only a stable error category, never the raw dependency error; connection strings, hosts and credential material are not returned by the probe or copied into logs.

Protected management reads, previews, exports, routing probes, audit reads and Queue mutation backend failures follow the same boundary. HTTP status, stable error code and mutation phase/effect evidence remain available, while backend-generated messages are replaced with code-specific safe text and logs retain only the stable category plus safe operation context. Client validation and precondition errors remain actionable because they are generated by the management service rather than an upstream dependency.

Validation: `go test -count=1 ./management/internal/config ./management/internal/app ./management/internal/api ./api`. Coverage includes loopback bind boundaries, GET/HEAD, both allowed roles, rejected credentials, absent auth configuration, forwarded-header spoofing and public bootstrap paths. These are local source tests, not production browser or release qualification evidence.
