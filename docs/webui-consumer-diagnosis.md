The exact Consumer response now includes `max_ack_pending`, copied from broker configuration without default substitution, including zero and -1. It is required in the current OpenAPI response; older servers may omit it. The UI then marks this evidence unavailable instead of assuming a limit. No NATS subtree, data path, configuration or authorization policy changes are made.

Consumer detail displays advisory comparisons from its exact Consumer read. It now also performs an independent `/api/v1/nodes` read and correlates reported Consumer Leader/Follower names only to uniquely matching, varz-identified configured endpoints. The UI shows the separate node-read completion time. A duplicate server name is ambiguous; no match is unresolved and never proof that a node is missing. Failed, stale, future or incomplete node reads remove current correlation without invalidating the separately retained Consumer observation. Node monitoring availability is not node health, complete cluster membership or an atomic snapshot with the Consumer read.

Positive pending count prompts comparison with later observations, not a growth claim. ACK-pending at or above a positive configured limit prompts investigation of processing and acknowledgment, only for explicit/all ACK policies. Pending messages with zero waiting pulls prompt checking the fetch loop, not declaring clients disconnected. Positive reported redelivery prompts investigation, not a rate or root-cause verdict. Zero counters and absence of hints do not imply health.

Counts are validated and compared as exact integers, never rounded JavaScript numbers. Pending allows uint64; other supported counts allow nonnegative int64. The configured limit also preserves -1; only positive limits trigger comparisons. Missing, malformed, out-of-range and unsupported values remain unavailable. No guessed field default supplies evidence.

Only a completed successful read within 30 seconds may produce current hints. Hidden-tab pause, refresh in progress, refresh failure, older data or a future timestamp clears current hints/facts; retained historical observations elsewhere in the page are not promoted to current diagnosis. Invalid/missing timestamps are unavailable. This freshness threshold is presentation policy, not a Consumer health boundary.
