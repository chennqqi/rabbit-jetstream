# WebUI 正式规划设计——运维管理控制台

[English](webui-design-plan.md) | [简体中文](webui-design-plan.zh-CN.md)

日期：2026-09-09。版本：**0.2，Queue 详情视觉方向已选定；契约仍待评审**。

## 1. 任务与范围

负责人在 [RabbitMQ 功能调研](webui-rabbitmq-requirements.zh-CN.md) 后要求启动正式 WebUI 规划。本计划将需求转化为页面规格、交互契约及交付门槛。当前已授权开展规划，并已选定 Queue 详情视觉方向；**尚未完成功能实现或发布批准**。各阶段由同一负责人评审和验收即可，不增加审批人员。

主要用户：兼任运维和开发的项目负责人，也会执行只读诊断及审计。核心目标：不必记忆 JSON 就能声明 Queue，找到积压证据，安全修改配置，并能查清操作结果。这是桌面优先的内嵌管理应用，不是营销网站，也不是 AMQP 兼容项目。

范围基线：**WEB-001–016（P0）**，保留单账号和原生 SDK 语义。P1 仍为 WEB-017–027、WEB-034，P2 仍为 WEB-028–033，不静默删减调研需求。

本轮不含：历史曲线、全局连接/Consumer 检索、载荷访问、清空/重放、批量变更、多账号管理、恢复、联邦及浏览器 SSO。P0 仍包含安全的读/写/审计策略和内存 Token 会话；无需等待 SSO 才落实授权。

不修改冻结制品或运行中的 Docker/裸机验收环境。后续仍在本机构建。UI/后端修改需要形成新候选版本及独立回归证据，现有稳定性测试不能为变化后的二进制背书。

## 3. 信息架构与页面清单

建议使用 `/admin/` 下的 History 路由，复用已有应用壳回退。静态资源使用以 `/admin/` 为根的稳定路径，保证详情直接打开和刷新可用。下表是**拟议 UI 路由，不是 HTTP API**。路径参数编码，页码/筛选/标签页写入 URL，Token 和未保存配置不得进入 URL。旧 `#overview`、`#queues`、`#nodes` 链接应映射到对应新页面。

| 页面 | 拟议路由 | 主要内容与操作 | 需求映射 |
| --- | --- | --- | --- |
| S-01 总览 | `/admin/overview` | 部署身份、健康证据、总数、问题、最后成功观测；进入受影响资源 | WEB-001、WEB-008、WEB-012、WEB-015 |
| S-02 Queue 列表 | `/admin/queues` | 服务端检索/筛选/排序、总数、分页、创建；列为名称、观测健康、存储消息、消费者数、存储、副本、版本 | WEB-002、WEB-009 |
| S-03 Queue 详情 | `/admin/queues/by-name/:queue` | 概况 / 配置 / 路由 / 消费者 / 事件；编辑及独立危险操作区 | WEB-005、WEB-007、WEB-009、WEB-013 |
| S-04 创建 Queue | `/admin/queues/new` | 引导表单、专家 JSON、明确部署上下文、校验和计划预览 | WEB-003、WEB-004、WEB-005 |
| S-05 编辑 Queue | `/admin/queues/by-name/:queue/edit` | 名称不可改、原始版本、未保存草稿、变更预览、冲突对比 | WEB-003、WEB-005、WEB-006 |
| S-06 Stream 列表 | `/admin/streams` | 分页只读列表，区分受管/外部资源 | WEB-002、WEB-010 |
| S-07 Stream 详情 | `/admin/streams/:stream` | 保留/容量、subjects、存储状态、副本证据、Consumer 分页 | WEB-010 |
| S-08 Consumer 详情 | `/admin/streams/:stream/consumers/:consumer` | Durable/filter/ACK/投递配置，待投递、待确认、重投及指标说明 | WEB-009、WEB-010 |
| S-09 节点列表 | `/admin/nodes` | 节点及获取错误，用稳定 ID 选择节点 | WEB-011 |

| S-12 访问与设置 | `/admin/settings` | Token 会话/清除、服务端提供的有效权限、开放模式、部署模式、语言、刷新偏好 | WEB-004、WEB-014、WEB-016 |

WEB-001/012/014/015/016 为跨页面需求，不限于表中标注处。Queue 的“事件”指关联的**管理审计事件**，不是消息投递历史。P0 的“路由”是只读计划表，交互路由工作区仍放在 P1。

路由决策：`new` 当前是合法 Queue 名称，因此资源详情使用明确的 `by-name` 前缀。`/admin/queues/new` 打开创建页，`/admin/queues/by-name/new` 打开名为 `new` 的 Queue，避免静默禁止合法名称。

## 4. 页面组成与字段行为

### 总览、列表与详情层次

固定顶栏：产品、部署名称/模式、观测时间、刷新、语言、访问入口。单账号上下文只显示标签，不提供无效租户切换器。导航分组：总览；资源（Queues、Streams、节点）；运维（审计）；设置。

总览先呈现问题，再呈现资源总数和节点摘要。没有历史源就不画速率曲线或迷你趋势图。统计不完整时明确标记，不能把已加载行数当总量。“当前问题”是观测结果，不代表已发送告警。近期审计按权限展示，没有访问权限不能显示为“没有变更”。

Queue 列表采用紧凑工具栏、稳定表头，默认每页 50，API 单页上限 200。全局检索/筛选/排序先于分页；后端没实现的能力不能伪装成全局筛选。窄屏保留名称和状态，次要列允许明确横向滚动。详情必须有可键盘访问的文本链接，整行点击只是可选快捷方式。

Queue 详情头部分别显示名称、声明版本、观测健康和新鲜度。概况关联声明与生成资源；配置注明单位和默认值来源；消费者区分待投递/待确认；路由解释支持的 binding→subject 映射；事件链接同一审计筛选结果。编辑使用完整页面，不嵌套详情弹窗。

### 创建/编辑表单契约

关联资源强制逻辑（审查补充）：Queue Consumers 必须先列表。解析计划中的一个 Stream 及托管 Consumers（主 Consumer 加额外优先级 Consumers），区分预期/缺失/外部资源，再先筛选排序、后分页。身份为 `(stream, name)`。详情/返回/深链保留查询和页码，精确有界查找不依赖当前已加载页。分别定义无资源、无匹配、无权限、缺失、部分失败、陈旧。概况指标明确 Consumer，不能任取第一条或汇总当前页。期望配置、已接受声明、观测资源独立存储。失败读取不能推进观测时间。KV revision/ETag 与内容生成的 plan revision 分离。规范化精确比较避免等价值写入。这些规则阻断 C-03–07 的生产关闭；[审查进展](webui-logic-review.zh-CN.md)单独跟踪模拟实现。

| 分组 | 字段与交互 | 校验 / 保留规则 |
| --- | --- | --- |
| 身份 | 名称、标签、部署模式 | 名称沿用字母/数字/下划线/连字符契约；编辑时锁定名称；标签双向转换不丢失。 |
| 路由 | 显式选择 subjects 或 bindings，可重复添加；binding 包含 exchange/type/keys | 至少一类有内容；已有内容时切换需确认；fanout 无 keys；通配符语义由后端校验。 |
| 存储与保留 | 副本、file/memory、带单位的时间/字节/消息数限制 | 区分设置值、默认值及不限额含义；不静默截断或推断新的生产资格。 |
| 投递 | ACK 等待、最大投递、可选优先级及 DLQ | 区分未设置优先级与显式零；DLQ 未解析时按后端规则报校验问题，不虚构成功。 |
| 复核 | 规范化声明、生成资源摘要、新旧差异、警告 | 比较语义而非空白符；显示所有应用的默认值；预览不写资源。 |

内存中只有一个规范化草稿，表单和专家 JSON 是两个视图，不是两套状态。非法 JSON 可恢复，不静默丢弃不支持字段；无法表单化的字段应阻止转换并说明。大整数不能被 JavaScript 不安全舍入，精确序列化必须与 Go 解析对照。默认值来自版本化服务端契约或显式固定版本的共享 Schema，不在前端独立猜测。

创建使用 `If-None-Match: *`，名称冲突不能自动变成更新。编辑保留初始声明及 ETag；后台刷新不得覆盖草稿或推进其前置版本。带未保存修改离开页面需确认。认证过期可将草稿保留在当前页面内存，主动清除会话应警告后清除敏感草稿；草稿及 Token 均不持久化。

### 写操作状态模型

| 状态 | 界面表现 | 允许的后续操作 |
| --- | --- | --- |
| 编辑中 | 草稿及初始版本 | 校验/预览，或放弃。 |
| 复核中 | 规范化差异、影响证据及观测时间 | 单次提交或返回编辑。 |
| 提交中 | 禁止重复提交，显示进度 | 等待结果；关闭页面不保证取消服务端操作。 |
| 已接受、观测中 | 请求接受与资源收敛分开展示 | 查询实际状态，不重新提交写入。 |
| 冲突 | 基线/本地/当前三方对比 | 显式重基、重新校验及复核；不自动合并不兼容修改。 |
| 已拒绝 | 字段/全局错误，保留草稿 | 修正内容或权限。 |
| 结果不确定 | 说明写入可能已经发生，显示可获取的关联 ID | 查看资源和审计，不自动重试写入。 |

删除独立处理：读取归属、配置版本及当前影响 → 展示精确名称和观测数据 → 输入确认（force 关闭）→ 条件删除 → 查看结果/审计。配置 ETag **不能冻结实时消息/消费者数量**。声明变化必须冲突；刷新发现影响变化应重新确认。“仍为空/未使用才允许删除”的强保证必须由后端/代理服务真正落实，而不是靠前端时间戳。定义前，应标明计数仅供参考及竞争窗口，不宣称原子、无丢失删除。

## 5. 健康、权限与失败状态

健康与新鲜度为两个维度。新鲜度建议：观测超过 30 秒标为过期，依据观测时间与经过时长计算，处理客户端/服务端时钟偏差；这只是控制台阈值，不是代理服务健康阈值。正常刷新仍为 10 秒，最多一个刷新批次在途，失败退避上限 60 秒。隐藏标签暂停后，旧数据不能继续呈现为最新。

| 证据 | 主状态 / 展示 |
| --- | --- |
| 没有成功证据，或必要来源不足 | 未知，说明缺失来源。 |
| 已确认受管资源缺失 | 缺失，列出具体资源。 |
| 已确认必要副本/资源故障 | 降级；其他来源不可用时也保留已知故障证据。 |
| 期望与实际计划不一致，暂无已确认故障 | 收敛中，显示差异及观测时间。 |
| 所有必要检查通过 | 健康，但仍注明新鲜度；不能只凭 Stream 存在推断。 |
| 上次成功过旧，或最新刷新失败 | 在最近状态上叠加过期/不可用标识，不替换为绿色结果。 |

每页分别设计：初次加载、确实无资源、筛选无结果、无权限、资源不存在、部分失败、过期成功、全部失败。各状态有不同文案及恢复动作。成功加载后的刷新保留已有数据和新鲜度，不重复用骨架屏遮挡。

建议授权矩阵（需后端实现；当前资源读取通常未受保护）：

| 操作 | 受保护部署中未认证 | Auditor | Operator |
| --- | --- | --- | --- |
| 读取资源 | 拒绝 | 允许 | 允许 |
| 读取审计 | 拒绝 | 允许 | 允许 |
| 创建/修改/删除 Queue | 拒绝 | 拒绝 | 允许 |
| 用户/账号管理 | 不提供 | 不提供 | 不提供 |

不隐含新增 viewer 角色。本地演示例外最多放开资源读取，不能绕过写入/审计。探针、指标必须明确逐路由策略，避免增加后台鉴权时破坏 readiness 或抓取。`/info` 和身份初始化需要明确哪些非敏感字段允许匿名。授权以服务端为准，不能在浏览器自行解码 Token 后就认为权限已验证。

## 6. 实现前需要明确的后端契约

以下是**待设计契约，不是已存在的新接口**。兼容时复用现有路由，实施前给出实际 Schema 和错误示例。

[API 接入规格](webui-api-contracts.zh-CN.md)现已记录经过代码核实的当前行为、C-01–07 扩展提案和 22 条验收用例。WP-02 仍待策略决策、可执行 Schema 及与实现一致的夹具完成；本规格不代表提议的接口已经存在。

| 契约 | 最低决策 / 证据 | 依赖需求 |
| --- | --- | --- |
| C-01 身份及开放策略 | 有效身份/权限、读策略、本地例外、探针/指标隔离、过期错误 | WEB-014；安全开放非回环访问 |
| C-02 部署与能力 | 部署意图、支持与已验收的副本/优先级、规范默认值、Schema 版本 | WEB-003/004 |
| C-03 列表查询 | 先检索/筛选/排序再分页、稳定次级排序、总数口径、限制及取消；承认资源变化，不承诺快照 | WEB-002/013 |
| C-04 观测 | 逐资源健康原因、必要证据集合、观测时间、来源错误；不支持与零分开 | WEB-008/009/011 |
| C-05 预览及并发 | 无副作用的规范计划/差异、原始版本、不安全转换、预览失效机制、最终写入前置条件 | WEB-005/006/007 |
| C-06 关联资源读取 | Queue→Stream 直接映射、受限 Consumer 查询及定向分页；详情不下载整个账号列表 | WEB-009/010 |
| C-07 审计查询 | 资源/操作者/时间筛选、关联、结果不确定、脱敏、新事件写入时的分页 | WEB-013/015 |

审计详情及 Consumer 详情可以先经受限集合查询获取；如果无法可靠定位某条记录，补明确查询契约，不下载全部事件/Consumer 模拟详情接口。C-03 必须评估实际后端枚举成本，而不只是限制 JSON 大小。

建议前端模块职责与框架解耦：API/认证传输、路由及 URL 状态、查询/新鲜度缓存、规范 Queue Schema 适配、写操作状态机、语言/格式化、表格/表单/状态/错误基础组件、页面编排。只访问同源 API，不直连 NATS，不使用持久缓存保存凭据或资源数据。后续资源交付还应通过版本化文件名或等价机制解决当前一小时静态资源缓存的更新问题。

## 7. 下一阶段视觉设计简报

从现有 Token 出发：正文 `#15211e`、次要文字 `#66726e`、底色 `#f6f8f6`、表面 `#ffffff`、边框 `#dce4e0`、导航 `#102a25`、操作绿 `#13795b`、警告 `#a15c00`、危险 `#b42318`。这是代码提取值，不代表所有组合的对比度已验证。保留系统字体回退，数字等宽排列，标识符使用等宽字体；不依赖远程字体或装饰图片。
