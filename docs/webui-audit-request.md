# Request-correlated audit evidence

[English](webui-audit-request.md) | [简体中文](webui-audit-request.zh-CN.md)

`GET /api/v1/audit/requests/{requestID}?before={sequence}` is a read-only operator/auditor endpoint. Request IDs accept 1–128 ASCII letters/digits or `_.:-`; `before` is an optional exclusive uint64 sequence cursor. Unknown/repeated/invalid parameters return 400. Existing audit authorization remains authoritative; unavailable/corrupt/backend failures return 503 without partial evidence. A five-second request deadline includes authorization.

Each call checks at most 256 retained sequence positions newest-first. Response fields are `requestId`, `items`, `streamPresent`, `firstSequence`, `lastSequence`, `scanned`, `missing` and `nextBefore`. Continue from `nextBefore` even if `items` is empty. Missing positions count toward the limit. Sequence integers require lossless decoding. No audit storage is created by this read.

This is a bounded compatibility scan over existing audit data, **not** an indexed full-history search, atomic snapshot, idempotency service or operation verdict. First/last sequences describe current retained storage. Null cursor means the traversal reached that observed lower boundary; it says nothing about expired, absent, future or unrecorded evidence. A missing Stream or empty matches never proves no execution. Retention can change between pages. Request IDs can be reused; inspect actor/resource/action and intent relationships rather than assuming a single attempt. Audit intent and outcome are separate persisted events; missing outcome does not prove failure. Durable request outcome resolution remains outstanding.

Unknown-write inspection reads the first audit window alongside declaration and Consumer evidence. “Read older audit window” follows the exclusive cursor even when no events matched the preceding window. Every acquired window retains its own range, gap count and read time. Read failures preserve prior windows/cursor and require explicit retry. Cursor progression, event identity, ordering and safe uint64 values are validated. Session clear suppresses late responses. Reaching the observed lower boundary does not imply no execution. Neither inspection nor paging unlocks writes or replaces the original ETag. Full standalone audit UI and explicit outcome resolution remain pending.
